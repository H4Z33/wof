# Build a local RF Online server safely

You can run RF Online on a local Windows machine in 2026 by choosing one of two stacks, and both depend on a matching official client. The first is the **leaked 2.2.3.2 ("2232", Golden Age / GU) server-file family**. It is the community's de facto standard, with the most guides, fixes, hooks, GameCPs and decompiled source. The second is the **GoMMO emulator from Old School Ops (OSO)**, a free but closed-source server written from scratch in Go. It ships ready-made bundles for Golden Age, 4.15 Age of Patron, 4.55 Dragonborn and four older versions, and runs on SQLite or MySQL with no MSSQL or ODBC setup ([oldschoolops.com](https://oldschoolops.com/), [OSO downloads](https://oldschoolops.com/downloads/)). Archive.org now holds hash-verified preservation copies of the 2232 clients, which gives a 2.2.3.2 setup the most verifiable client source ([ccrplay-2232](https://archive.org/details/ccrplay-2232), [playrf-2232](https://archive.org/details/playrf-2232)). Server source exists only as an old leak that does not compile, as 2025 Hex-Rays decompilations (about 43,877 .cpp files for 2232 and 37,745 .c files for 4.15), and as early hand-written C++ rebuilds. None of these is a ready-to-build project, and none is on GitHub ([RaGEZone 1253046](https://forum.ragezone.com/threads/release-2232-zoneserver-loginserver-accountserver-decompiled-source-code.1253046/), [RaGEZone 1253062](https://forum.ragezone.com/threads/415-zoneserver-c-source-file.1253062/)). On the legal side, Netmarble has owned the IP since 2020 and now sells RF Online Next worldwide. The leaked binaries and the circulating clients are its copyrighted property, so even a purely local instance is low-risk only in practice, not lawful ([Newsis](https://mobile.newsis.com/view.html?ar_id=NISX20200928_0001182283)). Downloads come through password-protected archives on MediaFire-style hosts, the same channel infostealer campaigns use, so run them only in an isolated VM. **Caveat on evidence:** RaGEZone, RFDev (rfdev.net) and rf-cheats.ru could not be reached from the research network (web filter, HTTP 403 and TLS errors). Every claim cited to those sites therefore comes from search-engine snippets rather than full posts, and download liveness, archive contents and exact config syntax there are unverified.

## Golden Age 2.2.3.2 is the build to target

The community traces the classic version line as Giga 3 → Giga 4 → 2.1.5 → 2.1.6 → 2.2.1 → 2.2.3 → 2.2.3.2, and calls 2.2.3.2 "probably the most stable and reliable version" ([RaGEZone version history](https://forum.ragezone.com/threads/the-version-history-of-rf-online.948192/)). The later 4.15 Age of Patron and 4.55 Dragonborn were the final major updates ([RF Online Wiki](https://wiki.rfdatabase.net/patch-notes)). RaGEZone's RF Releases board lists server packs for 2.2.3, EP2, 2.2.1, 1.5, 2.1.6 and Giga 4 Episode 2, with 2.2.3.2 GU at the centre ([RaGEZone RF Releases](https://forum.ragezone.com/community/rf-releases.479/)). Its download section carries an "Official – RF Online 2.2.3.2 Server Files" entry, first released May 30, 2024, and described by the uploader as "clean from my archives" ([RaGEZone download 65](https://forum.ragezone.com/downloads/rf-online-2-2-3-2-server-files.65/)). A slightly modified **2.1.5 server-plus-client pack** appeared in April 2025. Its known bugs are guild masters needing manual DB entry and taxes stuck at 10% ([RaGEZone 1244500](https://forum.ragezone.com/threads/rf-online-2-1-5-server-files-slightly-modified-client-slightly-modified.1244500/)). RFDev hosts "default" 2.2.3.2 server and client files for learning, but states that its server-files section is not supported ([RFDev topic 6](https://rfdev.net/topic/6-2232-default-server-and-client-files/)).

Leaked **4.15 Age of Patron** files exist, but they are rougher. In one thread the AccountServer was flagged 3/67 on VirusTotal. Users report reusing the 2232 RF_USER/RF_WORLD databases, building a separate BILLING DB, and running an un-updated PlayPark 4.15 client ([RaGEZone 1201977](https://forum.ragezone.com/threads/aop-4-15-server-files.1201977/), [RaGEZone 1258346](https://forum.ragezone.com/threads/age-of-patron-4-1-5-server-files-with-fix-bug-time.1258346/page-2)). No public 4.55 leak surfaced; that version is served by GoMMO. The "Giga 5/6/7" labels you see in requests do not map to any release in the sources, which go from Giga 4 straight to 2.1.5 (Episode 2). Treat those labels as informal or regional naming rather than separate server builds. "Novus" is the name of private servers running Age of Patron, not a version ([bestgames RF NOVUS](https://rf.bestgames.to/project/242)).

### Server source code: reference material, not a codebase

Three kinds of source circulate. The oldest is a "Client + Server + Engine" leak (including R3 engine source). Commenters describe it as a pre-Giga-3 beta that will not compile ([RaGEZone 615314](https://forum.ragezone.com/threads/release-rf-online-sourcecode-client-server-engine.615314/), [RaGEZone 1056553](https://forum.ragezone.com/threads/release-reupload-rf-online-sourcecode-client-server-engine.1056553/)). In 2025 DevtopZ released **Hex-Rays pseudocode of the 2232 ZoneServer** (around 43,877 .cpp files, with Account and Login to follow) and a follow-up "rf online code v2.0" in October 2025. A separate 4.15 ZoneServer dump came with the author's warning that every file must be refactored before a rebuild ([RaGEZone 1253727](https://forum.ragezone.com/threads/rf-online-source-code.1253727/), [RaGEZone 1254420](https://forum.ragezone.com/threads/rf-online-code-v2-0.1254420/), [RaGEZone 1253062](https://forum.ragezone.com/threads/415-zoneserver-c-source-file.1253062/)). A mid-2026 reverse-engineering write-up of ZoneServerUD_x64.exe documents startup, packet handling and fixed capacity limits of about 2,532 players and 30,000 monsters ([RaGEZone 1269875](https://forum.ragezone.com/threads/inside-rf-onlines-zoneserver-startup-and-entering-the-world.1269875/)). A "Native C++ 2.2.3.2 server" for Windows and Linux on MSSQL reached v1.0.0 beta around September 2026, with no replies at indexing time ([RFDev forum 10](https://rfdev.net/forum/10-server-client-files/)). GitHub searches for "ZoneServerUD_x64" and "rf online zoneserver" return nothing ([GitHub search](https://github.com/search?q=ZoneServerUD_x64&type=repositories)). The only GitHub repo calling itself an emulator, vasyater/dooa (MIT), is still marked "coming soon" ([GitHub](https://github.com/vasyater/dooa)).

### GoMMO is the only maintained reimplementation

GoMMO claims about 2.1M lines of Go in 8,010 files, written since January 2026. It speaks the original client protocol, scripts in Lua, and runs on Windows and Linux x64 ([oldschoolops.com](https://oldschoolops.com/)). OSO lists no public repository or licence, and no independent security review exists, so "from scratch" is the vendor's claim, not a verified fact. A community Docker Compose wrapper runs the rf2232 bundle with SQLite or MySQL 8.4. It imports about 2.7M game-data rows on first start and exposes ports 27800 (game), 27801 (launcher) and 8080 (web panel) ([mvolotov/RF-OSO-Docker](https://github.com/mvolotov/RF-OSO-Docker)).

On classic 2232 setups the server address is either hard-coded, so users hex-edit `RF.exe`/`rflauncher.exe`, or written by a launcher into the XOR-encoded `System\DefaultSet.tmp` before it starts `RF_Online.bin` ([RaGEZone: Getting RF Client to my Server](https://forum.ragezone.com/threads/getting-rf-client-to-my-server.917982/), [RaGEZone C# launcher 2026](https://forum.ragezone.com/threads/release-c-rf-launcher-patchmaker-2232-gu-free-updated2026.1253205/)). The GIGA FINAL collection includes a prebuilt `Just RF CCR2(127.0.0.1).exe`. That is exactly the kind of convenience binary to inspect rather than trust ([archive.org contents](https://ia903209.us.archive.org/view_archive.php?archive=/32/items/rf-online-giga-final-collection/RF%20Online%20GIGA%20FINAL%20Collection.7z)).

## The classic 2232 stack needs MSSQL, three databases and four processes

The leaked stack runs on **64-bit Windows** ("32-bit will not work") with 4 GB or more of RAM. Classic guides target MSSQL 2005/2008 or 2008 R2 Express in Mixed Mode with TCP/IP enabled. A Windows dependency pack (VC++ runtimes and .NET) must be installed first, or the executables throw side-by-side errors ([PriorityMMO guide](https://prioritymmo.boards.net/thread/55/guide-rf-online-server-setup), [rfworld t85](https://rfworld.forumotion.com/t85-rf-offline-2-2-3-2-gu-server-files-full-tutorial), [rfworld t535](https://rfworld.forumotion.com/t535-problem-and-solving-all-about-rf-offline)). A guide from about 2024 for modern Windows Server ships **Microsoft ODBC Driver 17** with the files and insists on a **default SQL instance**, because a named instance leaves the server unable to find its databases. That guide now returns 404 and survives only as a snippet ([ariq.nauf.al](https://ariq.nauf.al/blog/install-rf-online-private-server-on-windows-server/)). Without TCP/IP the ZoneServer hits a connection bug at login ([RF-Dev wiki](https://rf-dev.net/wiki/starter-guide/3-install-microsoft-sql-server-mssql-r3/)).

The setup sequence runs as follows. Restore **BILLING, RF_User and RF_World** from .bak with "Overwrite" into a non-default folder such as C:\RFDB, because restoring into MSSQL's default directory fails. Create an `rf` SQL login mapped to all three databases, plus the logins `rfrusaccount` (RF_User) and `rfrusworld` (RF_World), which are **hard-coded in the AccountServer and ZoneServer for NationCode=RU**. Other nation codes require tracing ODBC to discover their logins. Create three ODBC DSNs with the same names. Edit AccountSystem.ini, BillingSystem.ini, LoginSystem.ini, Login_Filter_Dev.ini (the GM list), rfacc.ini (copy it into ZoneServer\RF_Bin), WorldInfo.ini (ServerType must change from 1 to 0, or clients cannot connect), WorldSystem.ini (comment out the version-check key), ServerRate.ini (an ItemRootRate above 10 crashed the author's server) and the FireGuard fg.ini/fgrs.ini. Create the HBK and History folders. Start the processes in order: **AccountServerSD → BillingServer → LoginServer (type `/open`) → 64-bit ZoneServer**. Accounts are rows in `RF_User.dbo.tbl_rfaccount`, and GMs go in `tbl_StaffAccount` plus Login_Filter_Dev.ini ([PriorityMMO guide](https://prioritymmo.boards.net/thread/55/guide-rf-online-server-setup)). The 2017 GU repack omits BillingServer, uses LoginServerSD and ZoneServerUD_x64, and runs everything as Administrator ([rfworld t85](https://rfworld.forumotion.com/t85-rf-offline-2-2-3-2-gu-server-files-full-tutorial)). This variation shows that database names, executable names and step lists differ between repacks of the same leak, so follow the guide that shipped with your pack. For local play everything can stay on 127.0.0.1. For LAN or VM-to-host play, open **10001 (login) and 27780 (zone)** and put the reachable IP in the launcher, the ZoneServer GateIP and the LoginServer ([RaGEZone 2025 set-up](https://forum.ragezone.com/threads/2025-rf-server-set-up.1242748/), [RaGEZone: make your server online](https://forum.ragezone.com/threads/how-to-make-ur-rf-server-online.871306/)).

Most failures are ODBC and login mismatches. "AccountDB Connect Failed" means the RF_User login or DSN is wrong. "Connect World DB Failed" points to rfrusworld, the RF_World DSN or rfacc.ini. CashDB errors point to the BILLING DSN. Forum fixes include switching to the plain "SQL Server" driver, enabling Named Pipes, confirming NationCode=RU and re-restoring RF_World ([RaGEZone 991449](https://forum.ragezone.com/threads/zoneserver-connect-world-db-failed.991449/), [RaGEZone 849637](https://forum.ragezone.com/threads/accountdb-configuserodbc-failed.849637/), [RFDev CashDB](https://rfdev.net/topic/9-cashdb-error/)). A bank error is fixed by changing the `tbl_AccountTrunk` Trunk Pass column type to int ([rfworld t535](https://rfworld.forumotion.com/t535-problem-and-solving-all-about-rf-offline)). No source covers SQL collation, Windows 11-specific problems, the exact VC++ redistributable years, or whether stored procedures in old .bak files keep working after a restore into SQL 2019/2022. Expect to troubleshoot these yourself.

### Recommended path for a local Windows setup

**Path A, the fastest and cleanest-looking:** GoMMO Golden Age. Build a Windows 10/11 VM (Hyper-V or VirtualBox) with host-only networking and take a snapshot. Inside it, install the GoMMO Golden Age 0.8.0 bundle on SQLite, or use the RF-OSO-Docker compose file if you prefer containers. Download `ccrplay-2232` or `playrf-2232` from archive.org and **check the published SHA-256** before extracting. Install the client outside Program Files, drop OSO's `rflauncher.exe` into the client folder, and launch through it. Use the web panel on port 8080 for accounts. This path avoids MSSQL, ODBC and the hard-coded RU logins entirely ([OSO game clients](https://oldschoolops.com/docs/games/rf/game-clients/), [RF-OSO-Docker](https://github.com/mvolotov/RF-OSO-Docker)). For 4.55 or 4.15, use the matching GoMMO bundle, find the exact `RF_Online.bin` byte size from the table above, and run the GoMMO Client Patcher, which byte-patches out GameGuard and the expiry check with a backup and full restore ([OSO game clients](https://oldschoolops.com/docs/games/rf/game-clients/)).

**Path B, for learning the original server or hooking it:** the leaked 2232 stack. Use the same VM. Install SQL Server Express as a default instance with Mixed Mode and TCP/IP, plus ODBC Driver 17 or Native Client. Then follow the PriorityMMO or rfworld guide described above, add the archived but MIT-licensed **Yorozuya** hook for around 40 exploit fixes (VS2017 x64), and use the decompiled ZoneServer dumps as reading material ([goodwinxp/Yorozuya](https://github.com/goodwinxp/Yorozuya)). For Windows 10/11 client problems, the generic fixes are windowed mode in `R3Engine.ini`, compatibility mode, and the dgVoodoo2 D3D8 wrapper. No RF-specific report confirms that dgVoodoo2 is needed ([PCGamingWiki dgVoodoo 2](https://www.pcgamingwiki.com/wiki/DgVoodoo_2)).

## Tools and communities cluster around 2232 and RaGEZone

Open-source tooling is modest but real. It includes the 2.2.3.2-only GS Editor (Electron, MIT, archived 2023) and a 2232 `.dat` editor, Java and PHP GameCPs, and launchers in Go, Java, JS and C# ([bump44/rf-online-gs-editor](https://github.com/bump44/rf-online-gs-editor), [josuerf/rfo-serverdateditor](https://github.com/search?q=rfonline&type=repositories), [nunavx/RFOnline-GCP](https://github.com/nunavx/RFOnline-GCP), [uargb/rfolt](https://github.com/uargb/rfolt), [princerayz/RF-Online-MiniLaucnher](https://github.com/princerayz/RF-Online-MiniLaucnher)). For assets there is a 2232 quest viewer, a Blender 5.0 add-on for `.msh`/`.ani`/`.bn`/`.bsp`, and a .NET 8 map exporter that converts `.bsp`/`.r3m`/`.r3t`/`.spt` to glTF ([TheKingScott/QuestViewer](https://github.com/TheKingScott/QuestViewer), [cbb-rf-online-addon](https://github.com/Cardboard-box-a/cbb-rf-online-addon), [RFMapToolMain](https://github.com/xuevertalex-web/RFMapToolMain)). EDF encrypt/decrypt and EDF↔DAT converters come only as binaries from rflib.ru ([rflib.ru](https://rflib.ru/en/files)), and no open `.edf` parser exists on GitHub. Server protection beyond Yorozuya is closed or commercial: FireGuard ships with the 2232 files, CrespoGuard publishes only docs, and paid protection sources are sold on Russian forums ([CrespoGuard docs](https://github.com/CrespoCyberConsultingLLC/crespoguard-docs), [zone-game.info 20664](https://forum.zone-game.info/showthread.php?tid=20664)).

RaGEZone's RF Releases and RF Development boards remain the anchor for releases, with posts from 2025 and through September–October 2026 ([RaGEZone RF Development](https://forum.ragezone.com/community/rf-development.478/)). RFDev is the second English hub. rf-dev.net no longer resolves, and Russian sites such as rf-cheats.ru, ForumMaxi and GameRip.ru are mostly 2.2.3 archives and guides ([rf-cheats.ru archive](https://www.rf-cheats.ru/forum/archive/index.php/f-566.html), [ForumMaxi](https://forummaxi.ru/tutorials/article/288-%d1%81%d0%be%d0%b7%d0%b4%d0%b0%d1%82%d1%8c-%d1%81%d0%b5%d1%80%d0%b2%d0%b5%d1%80-rfonline-223-bsb/)). The live player scene sits mainly on Brazilian and Indonesian private servers listed on vote-driven toplists ([nostalgic.gg](https://nostalgic.gg/en/rf-online), [gtop100](https://gtop100.com/RF-Online)). Discord communities almost certainly carry much of today's coordination, but no public index surfaced them.

## Legal exposure scales with distribution and money

Netmarble acquired the original RF Online IP from CCR in September 2020, including operating and derivative rights ([Newsis](https://mobile.newsis.com/view.html?ar_id=NISX20200928_0001182283)). It closed the legacy game region by region: North America in February 2023, Indonesia in December 2023, PlayPark SEA around January 2024, and Taiwan, reportedly the last, on December 31, 2025 ([GameIndustry.ph](https://www.gameindustry.ph/article/rf-online), [RaGEZone 1254701](https://forum.ragezone.com/threads/last-official-rf-online-server-will-shutdown-in-2025.1254701/)). RF Online Next launched in Korea on March 20, 2025, passed $20M in revenue within a month, and went global on June 16, 2026 ([KED Global](https://www.kedglobal.com/newsView/ked202503100003), [Sensor Tower](https://sensortower.com/ko/blog/RF-Online-NEXT-surpasses-20-million-in-cumulative-revenue-one-month-after-launch), [Gamespress](https://www.gamespress.com/RF-ONLINE-NEXT-TO-LAUNCH-GLOBALLY-ON-June-16)). Searches in English and Korean found **no lawsuit, DMCA notice or police action specific to RF private servers**, and the github/dmca repository was not checked directly. The broader precedents are severe, though. Korea punishes commercial private servers with up to 5 years in prison or a 50M KRW fine ([Daeryun Law](https://www.daeryunlaw.com/ch/faq/detail/939)). Blizzard won an $88M default judgment against the Scapegaming WoW server ([Game Developer](https://gamedeveloper.com/game-platforms/blizzard-wins-88m-judgment-against-i-wow-i-private-server-owner)). Blizzard v. bnetd held that even a reimplemented emulator breached the EULA and the DMCA's anti-circumvention rules ([EFF](https://www.eff.org/cases/blizzard-v-bnetd)). The US §1201 exemption for games whose servers have shut down explicitly excludes persistent-world MMOs and never authorizes using leaked server code ([EFF](https://www.eff.org/let-game-fans-keep-abandoned-games-running)).

In practice the risk rises in this order: studying the protocol, running a solo localhost instance, a LAN server for friends, a free public server, and a monetized public server. Enforcement has landed almost entirely at the monetized end. Path A reduces exposure on the server side, because GoMMO is not leaked code if its claims hold, but it still uses a redistributed Netmarble client and patches out that client's protection. Path B runs leaked proprietary binaries outright. None of this is legal advice, and the rules differ by country.

### Safety checklist

No documented case of a backdoored RF package was found. Still, the AoP AccountServer VirusTotal flag, the password-protected MediaFire archives, and 2025 campaigns such as RenEngine (over 400,000 infections through modded game downloads redirected to MediaFire) justify treating every download as hostile ([GamesBeat](https://gamesbeat.com/cyderes-howler-cell-threat-research-uncovers-stealer-campaign-targeting-gamers/), [elitepvpers SRO](https://www.elitepvpers.com/forum/sro-private-server/5244747-every-psro-server-contains-viruses-me.html)).

| Step | What to do | Why |
|---|---|---|
| Isolate | Use a disposable Windows VM with a snapshot, host-only networking, and no shared folders or clipboard. Never use a machine that holds browser sessions, wallets or password stores | Infostealers (Lumma, StealC, Vidar) target exactly those ([CyberArk](https://www.cyberark.com/resources/threat-research-blog/cheaters-never-win-large-scale-campaign-targets-gamers-who-cheat-with-stealc-and-cryptojacking)) |
| Prefer verifiable sources | Use archive.org clients with published SHA-256 hashes, and GitHub tools whose source you can read | Hashes prove the file matches what the uploader published |
| Hash and look up | SHA-256 every archive, EXE and DLL, then search VirusTotal by hash instead of uploading private files | Compares copies across mirrors without leaking them |
| Read detections correctly | Generic packer or heuristic hits (Themida, VMProtect, GameGuard) are often false positives. Named infectors (Ramnit, Neshta, Jeefo, Virut) or stealers mean you discard the package | Private-server binaries are commonly packed ([elitepvpers SRO](https://www.elitepvpers.com/forum/sro-private-server/5244747-every-psro-server-contains-viruses-me.html)) |
| Distrust encrypted archives | Re-scan everything after extracting, inside the VM | Passwords stop scanners from inspecting contents |
| Block egress | Bind servers to 127.0.0.1 or the host-only adapter, block outbound internet, and watch with TCPView | A backdoor has to phone home |
| Check persistence | Run Autoruns and Process Monitor after the first launch | Reveals added services, Run keys and scheduled tasks |
| Lock the database | Change the shipped sa and RF logins, and never expose 1433, 8080 or AppServ/PHP panels to the internet | Packs ship old MSSQL with known default credentials |
| Avoid prebuilt shortcuts | Skip localhost-patched EXEs and closed "defense DLLs" unless you have inspected them | They are the easiest place to hide a payload |
| Stay private | Keep it non-commercial and do not redistribute clients or files | Enforcement focuses on distribution and money |

## Conclusion

The RF scene has quietly changed. For a decade, "running RF locally" meant fighting MSSQL 2008, ODBC DSNs and hard-coded Russian logins on a leaked 2232 build. In 2026 the shortest working route is a closed-source Go emulator paired with a hash-verified archive.org client. That route trades the old configuration pain for a new trust question, because nobody outside OSO can audit GoMMO. The decompiled ZoneServer dumps and the native C++ rebuild point toward a genuinely buildable 2232 server, but none of them is there yet. Anyone who wants code they can read and compile today has only Yorozuya and the tooling repos.

Timing also matters. Netmarble now has a live, revenue-generating RF Online Next on the same IP, which gives it a reason to enforce that it lacked while it was winding down the legacy game.
